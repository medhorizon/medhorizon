Five minutes from zero to a running research session. No account required.

<Steps>
  <Step title="Install">
    ```bash
    npm install -g @synsci/openscience
    ```

    Or without a global install, `npx synsci` runs the same workbench in one step. The install script (`curl -fsSL https://medhorizon.ai/install | bash`) drops a standalone `medhorizon` binary into `~/.medhorizon/bin`, and platform binaries are attached to every [GitHub release](https://github.com/medhorizon/medhorizon/releases).

    Linux requires kernel 5.1 or newer. Glibc builds require glibc 2.17 or newer, and musl builds are selected separately. CentOS 7's stock 3.10 kernel is not supported; use a newer host kernel or VM.
  </Step>
  <Step title="Set a provider key">
    ```bash
    export ANTHROPIC_API_KEY=sk-ant-...   # or OPENAI_API_KEY, GEMINI_API_KEY, ...
    ```

    Any provider works — bring your own key and it stays on your machine. `medhorizon keys add` gives you an interactive sign-in for providers that support it. See [Models](/openscience/models) for routing and reasoning-effort tiers.
  </Step>
  <Step title="Open the workspace">
    ```bash
    medhorizon
    ```

    The command starts a local server and opens the browser workspace: file tree, editor, terminal, and session history, with inline rendering for molecules, structures, genomes, and plots. See [Workspace](/openscience/workspace).
  </Step>
  <Step title="Give it a goal">
    Ask for the outcome, not the steps. The default `research` agent plans, reads, codes, runs, and reports:

    ```text
    Reproduce the headline result of arXiv:2305.13245 on a small model
    and tell me whether it holds at 125M parameters.
    ```

    Prefer the terminal? One-shot runs work without the browser:

    ```bash
    medhorizon run "Profile train.py and find the input-pipeline bottleneck"
    ```
  </Step>
  <Step title="Optional: connect Atlas">
    ```bash
    medhorizon login
    ```

    Connecting an [Atlas](/openscience/atlas) account records your research into durable graphs and unlocks a managed model route with spend controls. MedHorizon never requires it. See [Connect to Atlas](/openscience/atlas).
  </Step>
</Steps>

## Verify the install

```bash
medhorizon --version
medhorizon models        # configured providers and models
medhorizon skill list    # installed skills
```
